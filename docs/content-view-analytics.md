# PROVED 콘텐츠 방문 기록 (관리자 전용)

## 대상
- 에디토리얼 상세: `/editorial/<slug>/` (목록은 미집계)
- 고양이·강아지 제품 상세: `/food/cat/<slug>/`, `/food/dog/<slug>/`, SPA 상세 라우트
- 사료 목록·브랜드 목록·검색 화면은 미집계

## Supabase에서 확인
Table Editor에서 다음을 확인한다.

| 객체 | 의미 |
|---|---|
| `public.content_view_events` | 방문 1건당 1행의 원본 기록 (UTC timestamp) |
| `public.content_view_log_kst` | 한국시간, 방문자별 열람 순서, 건별 누적 조회수 |
| `public.content_view_totals_kst` | 콘텐츠별 누적 조회수, 한국시간 마지막 조회 시각 |
| `public.content_analytics_admins` | 로그인한 관리자 계정의 Supabase Auth UUID (조회 제외) |

방문 시간은 UTC timestamptz로 정확하게 저장하며, 한국시간 뷰는 `Asia/Seoul`로 변환한다. `visitor_id`는 브라우저에서 만든 임의 UUID이고 IP·이메일은 수집하지 않는다.

같은 방문자+같은 에디토리얼/제품은 서버에서 **최근 24시간** 기록이 있으면 새 행을 만들지 않는다. 다른 콘텐츠는 즉시 기록한다. 제품은 URL이 바뀌어도 **species + 제품 UUID**로 같은 콘텐츠로 식별한다. `previous_content_key`는 같은 탭의 직전 콘텐츠를 표시한다.

기록 테이블과 뷰는 `anon`과 `authenticated`에 SELECT 권한을 주지 않았으며 RLS도 적용했다. 공개 RPC는 입력 검증·콘텐츠 존재 여부·동시성 잠금·방문자당 24시간 300건 상한을 두었다. 조회수는 일반 방문자 페이지에 표시되지 않는다.

## 관리자 본인 방문 제외

### 브라우저 단위 제외(로그아웃 시에도 적용)
운영자가 사용하는 **각 브라우저**에서 다음 링크를 한 번 방문한다.

`https://proved.kr/editorial/?proved_ignore_views=1`

트래커가 브라우저 localStorage의 `proved_analytics_ignore=1`을 저장한다. 이 브라우저에서는 조회 요청을 보내지 않는다. 다른 기기·시크릿 모드에서는 별도로 설정해야 한다.

해제는 `https://proved.kr/editorial/?proved_ignore_views=0` 방문.

### 관리자 계정 전체 제외(로그인 상태)
`public.content_analytics_admins`에 운영자의 **확인된 Supabase Auth user UUID**를 한 행 추가하면, 해당 사용자는 로그인 상태에서 모든 기기에서 DB 함수가 조회수를 제외한다. 이메일이나 추정된 계정으로 자동 등록하지 않는다. 현재 실제 관리자 UUID 지정은 별도 작업이다.

기존 로그인 세션 토큰이 만료된 상태에서는 유효한 사용자 인증을 확인할 수 없으므로 트래커가 해당 방문을 전송하지 않는다. 관리자가 로그아웃한 다른 브라우저까지 계정으로 자동 식별하지는 않는다.

## 주의
- 직접 브라우저에서 렌더링된 페이지를 대상으로 하며, JavaScript 미실행 방문은 수집되지 않는다.
- 24시간 중복 제외는 브라우저별 방문자 UUID를 기준으로 한다. 쿠키/사이트 데이터 삭제, 다른 기기, 시크릿 모드는 다른 방문자로 취급될 수 있다.
- 수집되는 방문자 UUID는 가명성 식별자이므로 사이트 개인정보 안내에서 수집 목적·보관기간 등을 고지하는 것이 적절하다.
- PR 병합 전에는 `js/proved-header.js`에서 추적 스크립트가 로드되지 않으므로 DB 로그가 비어 있는 것이 정상이다.
