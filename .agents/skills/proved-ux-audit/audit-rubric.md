# Proved UX Audit Rubric

이 문서는 화면을 '예쁘다/별로다'로 평가하지 않고 사용자 과업과 신뢰 관점에서 일관되게 판정하기 위한 기준이다.

## Score dimensions

각 항목은 0–3으로 기록할 수 있다.

- 0 = 실패/막힘/오판 위험
- 1 = 큰 마찰
- 2 = 사용 가능하지만 개선 필요
- 3 = 명확하고 안정적

점수는 제품 등급이 아니라 감사용 진단값이다. 외부 사용자에게 공식 점수처럼 노출하지 않는다.

### A. Orientation

- 현재 위치를 이해할 수 있는가
- 화면의 목적이 한눈에 보이는가
- 이전/다음 단계 관계가 명확한가

### B. Action clarity

- 주요 행동이 무엇인지 알 수 있는가
- CTA 문구가 실제 결과를 설명하는가
- 비활성/처리중/완료 상태가 구분되는가

### C. Continuity

- 이전 선택/입력이 다음 단계에 보존되는가
- 뒤로가기/새로고침 후 과업이 불필요하게 초기화되지 않는가
- 등록·비교·계산 사이 이동 시 맥락이 유지되는가

### D. Information hierarchy

- 가장 중요한 정보가 가장 강하게 보이는가
- 숫자, 단위, 기준이 분리되지 않는가
- 보조정보가 핵심정보를 압도하지 않는가

### E. Decision support

- 사용자가 판단할 근거가 보이는가
- 사실과 해석이 섞이지 않는가
- 정보 부족을 추정으로 덮지 않는가
- Proved가 근거 없이 승자를 정하지 않는가

### F. Recovery

- 결과 없음/오류/미등록 상태에서 다음 행동이 있는가
- 오류 메시지가 무엇을 고쳐야 하는지 알려주는가
- 처리 실패 후 다시 시도 가능한가

### G. Responsive usability

- 모바일에서 단순 축소가 아닌 재구성인가
- horizontal overflow가 없는가
- 긴 텍스트/제품명/태그가 레이아웃을 깨지 않는가
- 터치영역이 충분한가

### H. Accessibility basics

- keyboard focus가 보이는가
- control label이 이해 가능한가
- 색상 하나만으로 상태를 전달하지 않는가
- prefers-reduced-motion을 존중하는가

### I. Trust

- 데이터 출처/한계/확인되지 않음이 정직한가
- 공식값과 계산 참고값이 혼동되지 않는가
- 과도한 시각적 확신이 없는가

### J. Return/share value

- 과업 완료 후 결과를 다시 볼 가치가 있는가
- 저장/공유 결과가 독립적으로 이해되는가
- 다음 기능 연결이 사용자의 기존 목적과 자연스럽게 이어지는가

## Heuristics specific to Proved

### Search and discovery

좋음:
- 사용자가 종/형태/조건을 좁힌 결과를 이해한다.
- 선택 상태를 쉽게 제거할 수 있다.
- 결과 없음에서도 조건 수정 또는 등록 흐름으로 복구한다.

나쁨:
- 원재료명 검색이 처방/건강목적 검색처럼 오해된다.
- 필터가 화면 밖으로 밀리거나 선택 여부가 불분명하다.
- 조건이 많아질수록 페이지 전체 구조가 무너진다.

### Product identity

좋음:
- 브랜드 + 제품명을 함께 보여준다.
- 동일 브랜드에서는 서로 다른 제품명 부분이 눈에 띈다.
- 건식/습식, 고양이/강아지 맥락이 혼동되지 않는다.

나쁨:
- A/B나 색상만으로 제품을 구별한다.
- 긴 이름이 잘려 핵심 차이가 사라진다.

### Nutrition data

좋음:
- 등록값, DM, 섭취량, 기준값이 어떤 의미인지 구분된다.
- Ca:P는 비율을 함께 보여준다.
- 정보가 없으면 구조는 유지하되 누락을 명시한다.

나쁨:
- 기준 라벨이 숫자보다 더 크게 보여 실제 값을 찾기 어렵다.
- 공식 열량이 없는 계산값을 공식값처럼 보이게 한다.
- 하나의 색으로 모든 숫자를 강조해 위계가 사라진다.

### Calculator

좋음:
- 단계 순서가 고정되어 학습 가능하다.
- 결과에서 사료별 g가 가장 먼저 읽힌다.
- 저장 이미지는 핵심만 남긴다.

나쁨:
- 입력칸이 중복되어 같은 값을 여러 번 넣게 한다.
- 저장 이미지 때문에 화면 결과의 유용한 분석까지 삭제한다.
- 이미지 생성 실패가 무반응으로 보인다.

### Registration

좋음:
- 사용자가 기다리는 동안 실제 진행 상태를 이해한다.
- 완료 후 원래 과업으로 돌아온다.
- 방금 등록한 제품을 다시 찾는 비용을 줄인다.

나쁨:
- 버튼 재클릭으로 중복 요청이 생긴다.
- 새 탭으로 맥락이 분리된다.
- 등록 완료 후 사용자가 어디로 가야 할지 모른다.

## Growth interpretation

UX 문제는 아래 중 하나와 연결해 설명한다.

- Acquisition support: 검색 유입 사용자가 첫 화면에서 이탈하지 않는가
- Activation: 첫 유용한 행동까지 얼마나 쉽게 도달하는가
- Engagement: 상세 → 비교 → 계산 같은 깊은 가치로 이어지는가
- Recovery: 실패 상태가 이탈로 끝나지 않는가
- Retention: 저장/기록/재확인 가치가 있는가
- Referral: 공유 결과가 읽기 쉽고 신뢰할 만한가

단순 pageview 증가를 위해 불필요한 단계를 추가하지 않는다. 좋은 UX는 같은 과업을 더 적은 마찰로 완료하게 할 수 있으므로 체류시간 감소가 오히려 개선일 수 있다.

## Finding template

```md
### UX-001 · P1 · Calculator registration recovery

- Route: /cat-food-calculator/ → /feed-registration/
- Viewport: 390px
- User intent: 등록되지 않은 사료를 추가하고 계산을 계속한다.
- Reproduction:
  1. 계산기에서 검색
  2. 결과 없음
  3. 사료 등록하기
  4. 등록 완료
- Expected: 기존 계산기로 복귀하고 등록 제품이 자동 선택되거나 검색어가 복원된다.
- Actual: ...
- Evidence: screenshot / observed behavior / code path
- Why it matters: 계산 과업을 처음부터 반복하게 해 이탈 가능성을 높인다.
- Rule: PD-040, PD-046
- Fix: ...
- Verify: 390 + 1440에서 동일 경로 재검사
```

## Regression checklist

PR UX 검토 시 최소 확인:

- [ ] 변경 화면 정상 경로
- [ ] 변경 화면 진입 전 단계
- [ ] 변경 화면 다음 단계
- [ ] back/refresh
- [ ] loading/empty/error 중 관련 상태
- [ ] 1440 또는 1024
- [ ] 390 또는 375
- [ ] applicable PD-* rules
- [ ] 주요 텍스트 line break
- [ ] horizontal overflow
- [ ] touch/click target
- [ ] 상태 보존
- [ ] 제품 식별성
- [ ] 데이터 누락 표현
- [ ] 수정 후 같은 시나리오 재검증
