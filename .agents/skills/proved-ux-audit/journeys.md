# Proved User Journeys

이 문서는 Proved UX Audit의 실제 검사 순서를 정의한다. 전체 감사에서는 Tier 1을 모두 수행하고, 변경 범위에 따라 Tier 2를 추가한다.

## Tier 1 — 핵심 사용자 가치

### J1. 처음 방문 → 서비스 이해 → 첫 행동

**Intent:** 처음 온 사용자가 Proved가 무엇을 해주는지 이해하고 바로 유용한 기능을 시작한다.

경로 예시:
`Home → 사료 찾기/조건으로 찾기 또는 계산기`

검사:
- 첫 화면에서 Proved의 역할을 과장 없이 이해할 수 있는가
- 행동 영역이 editorial statement와 경쟁하지 않는가
- primary/secondary action 위계가 보이는가
- 모바일에서 첫 행동이 과도한 스크롤 아래 묻히지 않는가
- header/subnav/footer가 일관적인가

성공 기준:
- 사용자가 설명 없이 주요 기능 하나를 시작할 수 있다.

### J2. 조건으로 찾기 → 후보 좁히기 → 상세 보기

**Intent:** 원하는 조건으로 후보를 좁히고 제품 정보를 확인한다.

경로:
`조건으로 찾기 → 폴더 선택 → 태그 선택 → 결과 → 제품 상세`

필수 변형:
- 태그 1개
- 태그 여러 개 AND
- 같은 태그 재클릭 해제
- 긴 taxonomy
- 결과 없음
- 모바일 375/390

성공 기준:
- 선택 상태와 결과 관계가 명확하다.
- 폴더가 커지거나 페이지가 흔들리지 않는다.
- 결과 없음이 막다른 길이 아니다.

### J3. 검색 → 상세 → 정보 이해

**Intent:** 알고 있는 제품을 찾아 영양/원재료/기준 정보를 읽는다.

검사:
- 제품명이 길어도 식별 가능
- 고양이/강아지, 건식/습식 구분
- 제품 기본정보 누락 시 구조 유지
- energy/water/Ca:P가 모바일에서 빠르게 읽힘
- DM/등록값과 기준 비교가 혼동되지 않음
- Product Tag Blob이 실제 정보와 연결되어 보임
- 공식 홈페이지/판매 링크가 정보 위계를 해치지 않음

성공 기준:
- 사용자가 제품의 핵심 정보를 과도한 해석 없이 파악한다.

### J4. 상세 → 비교 → 차이 판단

**Intent:** 두 제품의 차이를 스스로 판단한다.

경로:
`제품 상세 → 비교 추가 → 두 번째 제품 선택 → 비교`

필수 변형:
- 서로 다른 브랜드
- 같은 브랜드의 유사한 제품명
- 일부 정보 누락

검사:
- 정확히 두 제품이 명확히 식별되는가
- A/B 같은 익명 표기 때문에 혼동되지 않는가
- 실제 제품명 차이가 강조되는가
- missing data를 추정하지 않는가
- Proved가 승자/별점/빨강으로 우열을 강요하지 않는가
- 숫자와 해석의 위계가 적절한가

성공 기준:
- 사용자가 "왜 다른지"를 이해할 수 있다.

### J5. 계산기 정상 경로

**Intent:** 현재 급여 중인 사료 조합으로 하루 급여량을 계산한다.

경로:
`계산기 → 01 사료 → 02 반려동물 → 03 비율 → 04 결과`

검사:
- 시각/DOM/읽기 순서 일치
- 고양이/강아지 공용 논리가 깨지지 않음
- 사료 선택이 명확
- 입력 오류가 어느 필드의 문제인지 알 수 있음
- 결과에서 g가 가장 강하게 보임
- kcal는 보조
- Ca/P, 수분 분석은 화면 결과에 유지
- 저장 결과는 흰 배경의 요약 문서
- 저장 이미지 생성 실패/텍스트 잘림/과도한 crop 없음

성공 기준:
- 사용자가 결과 숫자를 잘못 읽지 않고 저장할 수 있다.

### J6. 사료 없음 → 등록 → 원래 과업 복귀

**Intent:** 계산/검색 중 제품이 없어도 작업을 포기하지 않고 등록 후 이어간다.

경로:
`계산기 또는 검색 → 제품 없음 → 사료 등록하기 → FEED REGISTRATION → 처리 → 완료 → return_to → pendingRegisteredFeed 복원`

필수 검사:
- 같은 창 이동
- 원래 계산기 종류/슬롯 상태 보존
- 중복 제출 방지
- 처리 중 progress state
- 약 13초 동안 무반응처럼 보이지 않음
- 주황색 짧은 안내
- 완료 후 location.replace 성격의 복귀 확인
- 뒤로가기 시 등록완료 화면 재노출 방지
- 검색 가능 시 자동 선택
- 아직 검색 불가하면 제품명 입력 상태라도 복원

성공 기준:
- 사용자가 등록 때문에 계산 과업을 처음부터 반복하지 않는다.

### J7. 결과 저장/공유 → 재사용 가치

**Intent:** 결과를 보관하거나 다른 사람에게 공유한다.

검사:
- 저장 이미지가 원본 화면보다 간결한가
- g가 가장 강한 정보인가
- kcal/ratio 설명이 보조 위계인가
- 흰 배경 유지
- PV/구식 warm-paper 표현이 돌아오지 않았는가
- 작은 화면에서도 이미지 생성 품질이 유지되는가
- 저장 후 원래 화면 상태가 사라지지 않는가

성공 기준:
- 결과물이 독립적인 문서로 이해 가능하다.

## Tier 2 — 신뢰·재방문·확장 가치

### J8. PROVED 데이터 읽기 / Editorial 학습

Intent: 숫자와 기준을 처음 보는 사용자가 DM/NFE/영양기준을 이해한다.

검사:
- 자연스러운 줄바꿈
- 중앙 정렬 규칙
- 제목 검정 금지
- 그래픽은 개념 설명을 실제로 도움
- 장식 이미지 때문에 핵심 설명이 밀리지 않음
- 읽은 뒤 상세/비교 데이터 해석에 연결 가능

### J9. 모바일 navigation recovery

Intent: 작은 화면에서 다른 기능으로 이동하고 다시 돌아온다.

검사:
- 375/390에서 header/subnav 겹침 없음
- safe-area
- touch target
- footer 2열 등 현재 모바일 규칙
- browser back 후 선택 상태 보존 여부

### J10. 데이터 누락/검수 상태

Intent: 정보가 완전하지 않은 제품에서도 신뢰를 잃지 않는다.

검사:
- 확인되지 않음/정보 부족 표현
- calorie 참고값 문구가 제조사 공식값처럼 보이지 않음
- 검수 대기 제품이 확정 데이터처럼 보이지 않음
- 구조 자체가 사라져 다른 제품과 비교를 어렵게 만들지 않음

## Growth-linked journey hypotheses

UX Audit은 아래 가설을 기록할 수 있으나, 분석 데이터 없이 결과를 단정하지 않는다.

1. **Activation:** 첫 방문 → 첫 검색/계산 시작률
2. **Discovery depth:** 검색/조건찾기 → 상세 이동률
3. **Decision depth:** 상세 → 비교 이동률
4. **Task completion:** 계산기 시작 → 결과 도달률
5. **Recovery:** 검색 실패/사료 없음 → 등록 → 원래 과업 복귀율
6. **Share:** 계산 결과 → 저장/공유 사용률
7. **Return value:** 저장한 결과, 체중 기록, My Score 등 다시 확인할 이유

문제를 발견하면 "어떤 사용자 행동이 막히는가"와 함께 연결한다.
